# Kernel evaluation

[← Spice CAD](../README.md) · Commands run from the repository root.

## SMLib browser evaluation

This records the browser evaluation against the original OpenCascade rack CLI.
The application now uses SMLib exclusively; the old CLI and rack configurator
have been removed. OpenCascade remains in test-only verification.

`evaluation/smlibwasm.html` recreates the default front-left part with
[`@classcad/smlibwasm`](https://github.com/awv-informatik/smlibpy/tree/main/js)
0.3.0. It includes both dovetail directions, the print orientation, STEP/STL
downloads, two rendered views, and mesh/STEP checks. The reference rack generator
used Rust and OpenCascade.

The October 14, 2026 evaluation passed on Linux with a Ryzen 9 5900X and
Chromium 154. OpenCascade imported the SMLib STEP and measured zero extra or
missing volume against the existing part. Both measured 95 × 174 × 161 mm and
203,856 mm³. Their rendered previews were byte-identical; both STLs had 200
triangles, closed consistently oriented meshes, and no overhangs beyond 45°.

Warm median construction times were **149.5 ms for SMLib WASM** and **317.6 ms
for the equivalent native OpenCascade build in release mode**. Each backend ran
five builds; the first was excluded. Import, export, rendering, compilation, and
process startup were excluded. SMLib's initial module import over local HTTP
took 294.5 ms. These are measurements of one planar part, not a general kernel
benchmark. Curved geometry, advanced fillets, female-joint samples, the complete
assembly, parameter sweeps, and MCP were not evaluated.

`evaluation/results.json` contains the raw measurements, checks, source hashes,
and limitations. Generated exports, preview PNGs, and the captured native
benchmark harness are in `output/evaluation/`. The candidate STEP is 57,078
bytes versus 187,550 bytes for the reference. STL size is not directly
comparable: SMLib emitted binary STL and the reference is ASCII.

The browser page and recorded timings are historical evaluation artifacts. Its
old `output/spice-rack-front-left.*` reference inputs are not generated by the
current application. Use the native verification suite for current geometry.

## Independent verification

The workspace defaults to `native/`; ordinary `cargo run`, `cargo test`, and
`cargo clippy --all-targets` build Spice CAD with SMLib only. The separate
`verification/` package has no executable and no dependency from the app. It
retains independent OpenCascade rack fixtures and geometry safety tests.

Build the app, then explicitly run the independent suite:

```sh
nix develop -c cargo build --locked
nix develop .#verification -c cargo test --locked -p spice-cad-verification
nix develop .#verification -c cargo clippy --locked -p spice-cad-verification --all-targets -- -D warnings
```

The suite invokes `target/debug/spice-cad` to construct and export Luau models.
Set `SPICE_CAD_BIN` to an absolute executable path when using a custom Cargo
target directory or testing a release build. Missing executables fail explicitly.
Checks reopen STEP files with OpenCascade and validate the imported B-rep with
`BRepAlgo::IsValid` (the standard `BRepCheck_Analyzer`), including geometric
checks. Volume comes directly from surfaces using adaptive Gauss–Kronrod
integration across B-spline spans;
non-finite results, failed integration, and estimated relative error above
`1e-8` fail verification. Closed oriented meshes, dimensions, part counts, and
print placements are checked separately. Independent rack fixtures
also exercise jar clearance, joints, fit samples, and support-free orientations;
they are test references rather than an alternative production modeler.
Mesh volumes must agree with surface volumes within 0.2%. Bounds still come
from imported meshes, avoiding conservative B-rep bounding-box padding when
checking bed contact.

Independent cavity and flanged-bushing fixtures check analytic volume and
cross-sections through the walls, bore, flange, and stem. Section comparisons
check missing and extra area, then compare line intersections within 0.001 mm.
Analytic volume and section-area comparisons allow 0.01% relative error for
curved STEP import and integration approximations. A deliberately misplaced
cavity proves that matching total volume and outer bounds cannot hide incorrect
internal geometry; a self-intersecting wire proves invalid B-reps are rejected.

Validation uses OCCT's standard geometric checker. Its optional exact method
reports curve-on-surface and same-parameter inconsistencies on current curved
imports that the standard checker accepts. This suite does not claim exact
curve/parameter consistency or general shape equivalence; STEP import can also
repair geometry before validation.

The default and CI Nix shells exclude OpenCascade. `.#verification` supplies
OpenCascade 7.8.1, its CMake setup, and the runtime libraries. Version-tag CI runs
this suite in a separate job that gates packaging; routine push/PR jobs run the
native suite. Use the verification shell for an intentional full-workspace test.

## Modify the verification engine

OpenCascade and opencascade-rs are source-available under their LGPL terms;
see `NOTICE` and `licenses/`. Their pinned versions are OCCT 7.8.1 and bindings
0.3.0. `flake.lock` pins OCCT through the Nixpkgs 24.11 input, while Rust tools
come from the current pinned Nixpkgs input. The bindings' `builtin` feature stays
disabled, so no OCCT submodule is needed.

For local binding changes, patch `opencascade` and `opencascade-sys` in the root
workspace's `[patch.crates-io]` section, update `Cargo.lock`, then rerun the
verification suite in `.#verification`. For kernel changes, override the `occt`
value used only by that shell in `flake.nix`. Keep kernel and binding APIs
coordinated. Application geometry continues to use the separately pinned SMLib.
